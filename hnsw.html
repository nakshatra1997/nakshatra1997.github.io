Skip Lists + HNSW: The “Express Lane” Idea Behind Fast Search

A beginner-friendly explanation with diagrams and a clear connection to how vector databases use HNSW for fast similarity search.

Beginner Friendly Vector DBs HNSW + Skip List

1) Why do we need Skip Lists or HNSW?

When data is small, you can search by scanning items one by one. But once you have millions of items, scanning everything becomes too slow.

Core idea: Don’t search everywhere slowly — jump quickly to the right area, then refine.

2) Skip List: A Sorted List With Express Lanes

The problem

Suppose you have a sorted linked list:

1 -> 3 -> 7 -> 9 -> 12 -> 15 -> 20 -> 25 -> 30

To find 20, a normal linked list may force you to walk step-by-step from the beginning.

The Skip List idea

A Skip List adds extra levels above the normal list. Upper levels contain fewer nodes and act like shortcuts (express lanes).

Skip list diagram

Level 2:  1 -------------- 12 -------------- 25
Level 1:  1 ------ 7 ------ 12 ------ 20 ------ 25 ------ 30
Level 0:  1 - 3 - 7 - 9 - 12 - 15 - 20 - 25 - 30

How search works

To find 20, you:

  • Start at the top-left
  • Move right until you would overshoot
  • Drop down a level and continue
Level 2:  1 -> 12   (next is 25, too far)
Level 1:      12 -> 20   ✅ found

Skip Lists are excellent for sorted data and fast exact lookups.

3) HNSW: Same “Express Lane” Idea, But For Similarity Search

Skip lists help you find exact values in sorted structures. But modern search problems are often like:

  • “Find the most similar documents to my query”
  • “Find images similar to this image”
  • “Recommend products like this one”

This is called Approximate Nearest Neighbor search (ANN), and one of the best-known approaches used in production systems is HNSW.

4) Real-Life Example: Finding the Best Café ☕

Imagine a city with 1,000,000 cafés. You search:

“Quiet café with wifi and good cappuccino.”

You can’t manually check all cafés. So you need a “navigation system” that quickly takes you near the best options and then helps you pick the closest matches.

5) What HNSW Builds (Graph + Layers)

HNSW builds a graph:

  • Nodes = items (cafés / vectors)
  • Edges = connections between similar items

The special part: the graph is arranged into multiple layers (like express roads).

HNSW layers diagram (conceptual)

Level 2 (highways):      A --------- D --------- H
                          |           |           |
Level 1 (main roads):    A --- B --- D --- E --- H --- J
                          |   /       | \         \
Level 0 (local streets): A-B-C-D-E-F-G-H-I-J-K-L-M-N

Sparse top layer = fast long jumps. Dense bottom layer = accurate local search.

6) How HNSW Search Works

Beginner intuition

Searching in HNSW is like a “hotter / colder” game:

  • Start at the top layer
  • Move to a neighbor only if it gets you closer to the query
  • When stuck, drop down a layer and continue

Search flow diagram

Query Q
   |
   v
[Level 2]  big jumps to reach correct region quickly
   |
   v
[Level 1]  smaller jumps to refine neighborhood
   |
   v
[Level 0]  local exploration to pick best nearest neighbors
Top = speed and Bottom = accuracy.

7) HNSW Insertion: Adding a New Café

Now imagine a new café opens: Café X. HNSW must add it into the multi-layer graph so it can be found in future searches.

Step 1: Decide how many levels Café X belongs to

HNSW randomly assigns a maximum level to a node (similar to how skip lists randomly promote nodes).

  • Most nodes → Level 0 only
  • Some nodes → Level 1
  • Very few nodes → Level 2+

Step 2: Navigate from top to bottom to find the right region

Starting from the top, HNSW moves through the graph to reach a neighborhood where Café X “fits” (i.e., where similar cafés exist).

Step 3: Connect Café X to nearby cafés

At each layer where Café X exists, it connects to a handful of nearest neighbors. 

Level 1:    X connects to D, E, H
Level 0:    X connects to E, F, G, H, I

Step 4: Prune extra connections

To prevent the graph from becoming too dense, HNSW limits the number of connections per node. Weak connections get removed.

8) Skip List vs HNSW (Connecting the Dots)

Concept Skip List HNSW
Problem type Exact lookup in sorted data Nearest neighbor (similarity) search
Navigation uses Value comparisons Distance comparisons
Speed comes from Express levels above the list Express layers above the graph
Shared principle Sparse top layers for fast jumps + dense bottom layer for accurate results

9) How Vector Databases Use HNSW

Vector databases store embeddings (vectors) for items like:

  • Documents
  • Images
  • Products
  • User profiles

A vector search query is typically: 

search(query_vector, topK = 10)

Brute force approach (slow)

Compare the query against every vector in the database: 

for each vector v in database:
    dist = distance(query, v)
sort and return topK

This needs O(N) distance computations. With millions of vectors, it’s expensive.

HNSW approach (fast)

HNSW builds a navigable multi-layer graph index. During search, it only visits a small subset of nodes, while still returning near-perfect nearest neighbors.

Vector DBs use HNSW to deliver fast semantic search, recommendations, and RAG retrieval without scanning the full dataset.

10) HNSW Tuning Knobs (Simple Explanation)

M

Max number of connections per node.

  • Higher M → better accuracy, more memory
  • Lower M → smaller index, faster build

efConstruction

How carefully the graph is built during insertion.

  • Higher → better graph quality
  • Higher → slower indexing

efSearch

How much the search explores at query time.

  • Higher → better recall
  • Higher → slower query

Quick analogy

  • M = number of roads leaving each café
  • efConstruction = how well planners designed the map
  • efSearch = how many nearby streets you check before deciding

11) Final Summary

A Skip List speeds up exact searches in a sorted list by adding multiple express lanes. HNSW applies the same hierarchical idea to similarity search by building a multi-layer graph: sparse top layers allow fast jumps, and the dense bottom layer refines to accurate nearest neighbors.

This is why vector databases widely use HNSW for real-time semantic search, RAG retrieval, and recommendation systems—fast and scalable without scanning millions of embeddings.
