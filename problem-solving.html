The Ultimate Problem Solving Framework

A repeatable thinking process for coding interviews. Learn how to understand, break down, and optimize problems systematically.

Problem Solving Interviews Algorithms

Goal

The objective is not to memorize hundreds of solutions, but to build a repeatable thinking process so that when you see a new problem, you know:

  • How to understand it
  • How to break it down
  • How to identify patterns
  • How to move from brute force to optimal
  • How to code with fewer bugs
Remember: A slow correct solution is better than a fast wrong solution.

Step 0 — Identify What the Problem Wants

Before thinking about algorithms, identify the goal. Most problems ask for one of four things:

1. Find Existence

"Does something exist?" (e.g., Target sum, valid path)

Patterns: HashSet/HashMap, DFS/BFS, Binary Search, Union Find

2. Find Count

"How many ways?" (e.g., Count paths, subsets, modulo 10^9+7)

Patterns: Dynamic Programming, Prefix Sum, Combinatorics

3. Find Best Answer

"Find minimum / maximum / longest / shortest"

Patterns: DP, Greedy, Heap, Sliding Window, Binary Search on Answer

4. Generate All Results

"Return all combinations, permutations, or paths"

Patterns: Backtracking, DFS

Step 1 & 2 — Read and Trace

Read Twice

  • First Read: Understand the story. Ask: "What exactly needs to be returned?" (Don't think about code yet).
  • Second Read: Extract Input, Output, and Constraints.
    • Is size 10^5? O(n²) probably fails.
    • Can input be empty? Negative? Duplicates? Sorted?

Solve Examples Manually

Take the sample input and trace every step manually. Create your own tests:

  • Small Case: [] or [1]
  • Normal Case: [1, 2, 3, 4]
  • Breaking Case: Duplicates, negatives, large values.
If you cannot solve it manually, do not code yet.

Step 3 — Identify the Pattern

Look for signals in the problem description to map it to a known pattern.

Data Structure / Domain Signal Likely Pattern
Arrays / Strings Need fast lookup ("Have I seen this?") HashMap / HashSet
Arrays / Strings Contiguous subarray (longest, shortest, window) Sliding Window
Arrays / Strings Sorted Array Binary Search, Two Pointers
Trees Explore nodes / Level order DFS / BFS
Graphs Shortest path / Connected components BFS, Dijkstra / DFS, Union Find
Top K / Choices / Opt. Largest K / Generate all / Maximum, Minimum Heap / Backtracking / DP or Greedy

Step 4 & 5 — Brute Force and Optimize

Never jump directly to clever solutions. Ask: "If performance did not matter, how would I solve this?"

Now ask the important question: "What work am I repeating?" That question creates optimization.

5 Common Optimization Transformations

1. Searching Again and Again

O(n²) nested loop searching → Use a HashMap for O(n).

2. Calculating Again and Again

Same result calculated multiple times → Use Memoization/DP.

3. Checking Every Range

Generating every subarray O(n²) → Maintain a changing Sliding Window for O(n).

4. Repeated Minimum / Maximum

Need top K or median → Maintain a Heap.

5. Answer Space is Searchable

"If X works, does every bigger value work?" → Binary Search on Answer.

Step 6 — Complexity Validation

Before coding, verify if your target complexity works with the given constraints (n).

Constraint (n) Target Time Complexity
n ≤ 10O(n!)
n ≤ 20O(2^n)
n ≤ 1,000O(n²)
n ≤ 100,000O(n log n) or O(n)
n ≥ 1,000,000O(n) or better

Step 7 to 9 — Execute and Verify

7. Define Your Invariant

Experts always know what their algorithm maintains. If you cannot define the invariant, your solution is unclear.

  • Sliding Window: "My window always contains valid elements."
  • HashMap: "My map contains previously seen values."
  • Heap: "My heap always stores the best K elements."
  • Binary Search: "Left side impossible, right side possible."

8. Code the Solution

Follow clear thinking order:
1. Handle edge cases (empty, null) → 2. Write main logic → 3. Return answer.

9. Test Before Submitting

Always test against: Given examples, empty input, one element, duplicates, negatives, sorted/reverse sorted, large inputs.

When Completely Stuck

1. Draw It

Draw boxes for arrays, nodes for trees, circles for graphs. Visualization reveals patterns.

2. Reduce the Problem

Solve for n=1, n=2, n=3, then generalize.

3. Change Perspective

Instead of "For every start", try "For every end". Instead of "For every element", try "For every pair".

4. Re-read Constraints

Constraints are hints. Small n = brute force allowed. Modulo = likely DP or counting.

Post Problem Review

Growth happens after solving. Maintain notes for each problem answering:
